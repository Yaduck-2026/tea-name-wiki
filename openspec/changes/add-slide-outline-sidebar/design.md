# Design

## Context

動機見 proposal.md。現況：`site/slides.html` 的結構是頂端列（回首頁、張數）、`#stage` 投影片區、底部翻頁按鈕與進度條。`slides.js` 讀取 `deck.json`（每張有 `title`），以 `location.hash`（`#1`～`#N`）切換投影片，`go()` 會先更新目前張數再改 hash。版面寬度上限 1100px；760px 以下切換為手機版排列。

## Goals / Non-Goals

**Goals:**

- 一鍵跳到任一張投影片，並隨時看得出目前在哪一張。

**Non-Goals:**

- 不做縮圖、搜尋或章節分組。
- 不跨裝置或跨瀏覽器同步開關狀態。
- 不修改建置程式或 `deck.json` 格式。

## Decisions

**1. 目錄由 slides.js 依 `deck.json` 產生。**
每項是 `<a href="#N">`，文字為「N. 標題」。沿用現有的 hashchange 流程，不另寫跳頁邏輯；標題永遠和投影片一致。
- 替代方案：建置時把目錄寫進 HTML。會多一份要同步的輸出，沒有好處。

**2. 版面：桌機兩欄、手機抽屜。**
- 桌機（761px 以上）：在 `body` 加上 `outline-open` 類別時，頁面以 CSS grid 分成左側約 260px 的目錄欄與右側投影片區；頂端列與翻頁列保持跨整寬。整體寬度上限由 1100px 放寬到約 1360px，讓投影片不會因側欄而變窄太多。
- 手機（760px 以下）：目錄為 `position: fixed` 的左側抽屜，寬度約 82vw（最多 320px），背後加半透明遮罩；開啟時頁面不捲動。
- 預設狀態（使用者確認）：桌機第一次預設隱藏；讀者按「目錄」後把選擇存在 localStorage（鍵 `teawiki.slides.outline`，值 open／closed），下次載入時套用。手機一律預設收起，手機上的開關不寫入記憶。讀寫 localStorage 都包在 try/catch 中，失敗時視為隱藏。
  - 替代方案：不記憶、每次回到預設。使用者希望自己決定後能保持，不採用。

**3. 「目錄」按鈕與無障礙。**
按鈕放在頂端列左側（「← 茶名有解」旁），具 `aria-expanded` 與 `aria-controls`。目錄是 `<nav aria-label="投影片目錄">` 內的有序清單；目前那一項加 `aria-current="true"` 與醒目樣式，並在換頁時 `scrollIntoView({ block: 'nearest' })`，確保長清單中看得到。
- 手機抽屜開啟時，焦點移到目前那一項；按 Esc、點遮罩或點選某一項時關閉，焦點回到「目錄」按鈕。
- 桌機的側欄是頁面的一部分，不搶焦點。

**4. 與既有鍵盤翻頁的互動。**
方向鍵翻頁維持全域有效（焦點在目錄連結上也一樣），與目前行為一致；Esc 只在手機抽屜開啟時處理。

## Risks / Trade-offs

- [桌機開啟側欄後投影片區變窄，圖文兩欄可能擠] → 放寬整體寬度上限；在 761～1100px 這段寬度實測第 1、5、8、12 張，必要時讓圖文兩欄在較窄時改為上下排列。
- [前端行為沒有自動測試] → 以瀏覽器逐項實測規格情境，並在建置測試確認輸出含目錄區塊。

## Migration Plan

實作後本機測試、建置與瀏覽器實測通過，再 commit 並 push，自動部署上線。回復方式：revert 該 commit。
