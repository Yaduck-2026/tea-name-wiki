# 可重複使用的 AI 任務指令

以下為之後可交給 AI 的任務範例，不表示現階段已執行。新增內容前應確認目前階段允許執行該任務。

## 新增一篇知識條目

> 請先閱讀 AGENTS.md、README.md、docs/content-guide.md 和 docs/progress.md。我要新增「[主題]」的知識條目，主分類為「[既有分類]」。先檢查是否已有同義條目，再查找可讀原始來源並保存研究紀錄。使用 templates/wiki.json 建立內容，補 sources/registry.json、局部引用及相關條目。未查清的部分保持草稿，不捏造資料。完成後執行目前已存在且適用的檢查並更新進度，說明實際改動和限制。

## 新增完整茶名拆解

> 請依專案規則，處理這個完整茶名：「[完整名稱]」。先核對來源，保留原詞順序，區分產地、品種、茶類、製法、風格、季節等角色。使用 templates/tea-name.json，附逐詞來源與白話翻譯，不從名稱猜測缺少的資訊。區分真實來源茶名或組合示例，未確認詞語不公開成正式知識。補上既有條目連結與文末來源，更新進度。

## 更新近一週話題

僅在使用者手動發出搜尋或更新要求時使用；沒有自動執行或背景排程。

> 請依 AGENTS.md 的取樣規則，以本次研究時間為終點，觀察台灣時間往回 7 天的公開 Threads、Instagram 茶知識討論。記錄實際搜尋、日期、讀取限制、帳號、貼文與可比較數據，去重後選出樣本中的討論焦點。統整後用官方、研究或專業原始資料查證，分開記錄社群說法與查證結果。用 digest 模板保留觀察期間，文末附帳號、原貼文及查證連結。資料不足就提供真實限制紀錄，不虛構熱門排名。此任務只執行本次更新，不建立背景排程。

## 依規則檢查延伸能力

> 請依既有模板新增一篇有來源的新條目，沿用目前分類及共用版型。確認新增內容能自動進入索引、搜尋及關聯，不逐頁修改 HTML。執行已建立的 check、build 並檢查實際頁面；如果工具尚未存在，就回報缺少的實作，不宣稱成功。記錄為什麼只靠 AGENTS.md 和模板就能完成這次延伸。
