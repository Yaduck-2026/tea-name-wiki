## API 與檔案驗證

| 情境 | 驗證結果 |
| --- | --- |
| 本機工作階段／跨來源 | 無 cookie 拒絕讀取；跨 Origin 拒絕寫入；任意 raw 路徑不可直接存取 |
| 本人登入 | 首次密碼設定、scrypt 不含明文、錯密碼拒絕、正確登入、登出後舊 cookie 失效、已設定後不可被匿名覆寫 |
| 上傳原件 | 真正保存 bytes，manifest hash 相符，來源為 draft，工作為 pending；下載與原 bytes 一致 |
| 錯誤檔案 | 重複檔、執行檔、假 PDF、超過 10 MB 均拒絕，不留下假來源 |
| 保存／重讀／索引 | 修改真正寫入 Markdown，重新讀取可見；索引與操作紀錄更新 |
| 衝突與版本 | 過期 revision 被拒絕，舊版可還原，原件 manifest 不被編輯操作改動 |
| 失敗回復 | 失效連結或未勾複核的公開保存被拒絕，原條目保持不變 |
| 完成整理 | 來源未複核或未整合知識時不可完成；符合條件後才可完成 |
| 公開輸出 | 不含 raw 目錄、使用者政策原文、草稿、待整理來源或本地備份；admin 為 demo 模式 |
| 公開倉庫可攜性 | 副本移除私有原件後，public 檢查與建置可通過；嚴格模式仍指出遺失 |
| Markdown 預覽 | HTML 圖片事件及 javascript 連結不會執行，正常文字標示仍能呈現 |

## Chrome 實際互動

1. 總覽統計載入。
2. 搜尋書架條目。
3. 使用真實 file input 上傳資料，確認 raw 檔案存在。
4. 新增草稿，保存後重開，確認 Markdown 檔案存在。
5. Markdown 即時預覽與不執行 HTML 的行為。
6. 手動執行健康檢查並顯示結果。
7. 390×844 手機版無橫向溢出；桌機使用 1440×1000。
8. 從管理介面按鈕產生公開版本。
9. 公開閱讀站載入、搜尋、閱讀文章，沒有 raw 維護連結。
10. 公開 admin 展示有明確提示，保存／上傳按鈕停用。

## 測試中修正

- 保存／還原時累積多餘空白行：統一 frontmatter 與正文分隔，還原重讀一致。
- log 指向草稿被錯判公開失效：index／log 為不公開的維護文件，可指草稿；其他公開內容的限制維持。
- 首次建立工作清單被當成外部變更：只針對原先存在檔案建立基線，保留真正的衝突檢查。
- Chrome 在此環境啟動 renderer 需隔離測試的 no-sandbox 參數；僅使用獨立測試設定檔，沒有操控使用者既有瀏覽器。驗證腳本已加連線逾時與連線清理。

## 實際限制

工具不提供模型自動摘要、事實判定、PDF OCR、社群自動搜尋、雲端多人登入或原件刪除。GitHub Pages 只部署閱讀站及唯讀展示，真實管理操作在本機 Node 服務完成。

健康檢查通過不代表茶內容已重新查證；八個既有外部來源的全文仍待手動取得。GitHub workflow 的遠端成功與正式網址須在上傳後另外確認。
