# TeaWIKI 管理介面使用說明

## 啟動

電腦需有 Node.js 20 以上，不需要安裝 npm 套件。

Windows 可雙擊專案內的 [run-admin.cmd](../run-admin.cmd)，或在專案資料夾執行：

```powershell
npm.cmd run admin
```

開啟 [http://127.0.0.1:4318](http://127.0.0.1:4318)。保持終端機運作；停止服務按 Ctrl+C。若 4318 已被使用：

```powershell
npm.cmd run admin -- --port=4319
```

服務只在本機使用，不要把這個沒有多人登入的後台改成公開監聽。

## 本人登入與訪客唯讀

第一次開啟管理頁，請自己設定至少 10 字元的密碼，之後以此密碼登入。沒有預設密碼，也不用把密碼傳給 AI。未登入不能讀取管理資料或上傳、編輯、還原、下載原件。

右上角可登出；工作階段最多八小時，服務重啟後需重新登入。密碼以 scrypt 加鹽雜湊存 .local/admin-auth.json，不含明文，該資料夾不提交 GitHub。忘記密碼需由本人在本機處理設定，不提供公開的無驗證重設入口。

一般訪客到公開閱讀站觀看；公開 admin 展示無寫入服務，即使改動瀏覽器按鈕也不會取得編輯權。這是公開唯讀站加本機私人管理的架構，尚不是可從公開網址登入寫入的雲端後台。

## 來源上傳與整理

1. 開啟「來源與匯入」，選擇或拖放 MD、TXT、PDF、CSV、JSON，單檔最多 10 MB。
2. 填名稱，可填具體來源網址；代號預設自動填入，也可調整。
3. 保存後，原件寫入 raw/articles/，manifest 追加 SHA-256；來源草稿出現在 Wiki，工作加入待整理清單。
4. 點「開啟整理」，可下載封存原件。PDF 僅封存，不自動擷取文字或 OCR。
5. 管理者或協作 AI 閱讀、摘要、查證，再整合相關知識；工具沒有內建模型，不會假裝完成這些工作。
6. 來源摘要複核後設為可公開，並整合至少一篇引用它的可公開條目，才能在清單按「完成整合」。

「原件已封存」只表示本地原檔已保存，不代表資料真實或已查證；上傳來源預設 draft。

## 編輯、預覽與還原

- 書架支援標題／摘要／別名搜尋、分類與狀態篩選。
- 新增條目時選類型與六大分類；既有 ID 及位置保持穩定。
- 編輯區顯示 Markdown 與即時閱讀預覽；原始 HTML 不執行。
- 勾選來源、相關條目後，保存時補上連結；正文仍要交代哪些說法依據何處。
- 標為可公開前勾選複核確認。這只是內容狀態，不是已上傳 GitHub。
- 保存先在隔離暫存副本執行檢查；不通過時不提交修改。成功後保留舊版、更新索引並追加日誌。
- 已有檔案被其他操作修改時會拒絕覆蓋；請重新載入並比對。
- 「歷史版本」可還原先前 Markdown，還原前的版本也保留；不提供原件修改或刪除。
- 索引與 log 由流程維護，不開放任意覆寫。

本機版本備份與整理工作在 .local/，不提交到 GitHub。請另外備份整個專案及 raw 原件；GitHub 不會保存被忽略的本地原件。

## 檢查與公開版本

健康檢查只檢查本地格式、來源、索引、連結與原件指紋，不判定事實，也不自動搜尋。

「使用說明 → 產生公開版本」會重建 dist/，可從右上「公開閱讀」預覽。每次編輯後需手動重新產生公開版本，不會自動部署。

命令列等效操作：

```powershell
npm.cmd run check
npm.cmd run build
```

公開輸出只選擇 published 概念、茶名、合格來源摘要及近期觀察；排除內部政策／示範問答、log、raw、研究檔、草稿與本地備份。Markdown 裡指向非公開維護檔案的連結，在公開頁轉為純文字。

## GitHub 版本的界線

GitHub Pages 是靜態網站，提供公開閱讀站及唯讀管理展示。真正上傳、保存、版本還原仍在本機服務使用；管理展示不會假裝保存成功。

公開 Repository 缺少被忽略的本地原件時，可用 `node scripts/check.mjs --public` 驗證；缺原件列為提醒，仍會檢查所有實際存在原件的 hash。本機嚴格的 `npm run check` 則會將遺失原件視為錯誤。管理服務採可攜模式檢查，不阻擋公開副本新增資料，但下載缺少的舊原件會明確回報不存在。

GitHub 設定見 [發布說明](github-publishing.md)。如果日後需要多人共用的線上可寫後台，需要另建身分驗證及後端；目前沒有對外提供該功能。
