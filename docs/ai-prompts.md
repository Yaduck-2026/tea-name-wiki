# 手動操作 TeaWIKI 的指令

這些文字交給協作 AI 執行，不是網站聊天功能，也不會自動排程。

## 匯入提供的資料

> 請先讀 AGENTS.md、內容指南及 wiki/index.md，將我提供的這份資料匯入 TeaWIKI。先辨識已有知識及來源，再保存取得的版本、建立來源摘要，整合受影響頁與關聯，保留差異及限制。最後更新索引、追加 log、執行 check 並報告實際改動。只處理我提供的資料，不另外搜尋。無全文要明示是 reference-only，不將摘要當原件。

## 搜尋近一週茶知識並匯入

> 請依專案規則，查找本次研究截止時間往回七天的公開茶知識討論。記錄實際搜尋、平台、帳號、原貼文、日期與可比討論數據，統整後使用指定官方及專業原始資料查證，再匯入 raw／Wiki，修改相關頁而不是只增加孤立文章。文末分社群與查證來源。資料不足就留下真實觀察限制，不虛構熱門話題；本次不要建立排程。

## 只根據 Wiki 回答

> 請先讀索引與相關頁，回答「[問題]」，引用具體 Wiki 及來源，說明已知與缺口，不對外搜尋。只記錄實際 query，不自動把答案存成新茶知識頁。

## 將比較結果存回

> 請將剛才有依據的比較整理進 Wiki，先檢查是否已有同義頁，選擇合併或建立 synthesis，補來源、雙向關聯及限制。更新索引、log 與進度，執行本地 check，不額外搜尋。

## 健康檢查

> 請做一次 lint：先跑 npm run check，再閱讀相關頁找術語混用、互相矛盾、過期與缺來源的說法。工具結果與內容判斷分開，能用既有資料修正的就修正，需要新研究的留問題清單，不擅自搜尋。記錄實際檢查範圍與限制，再追加 log。

## 新增茶名拆解

> 請用 Markdown 茶名模板處理「[完整茶名]」，保留順序，逐詞解釋角色與例子，引用既有來源，不猜沒寫出的資訊。來源不足保持草稿並說明缺口。明示是組合示例或真實來源茶名；詞語角色核對不等於商品認證。同步相關知識頁、索引與 log。
