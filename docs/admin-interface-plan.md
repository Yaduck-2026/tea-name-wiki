# TeaWIKI 管理介面｜本輪實作範圍

2026-11-16。依使用者要求製作並測試管理網頁，通過後準備上傳 GitHub；本輪先完成本地成果，不直接發布未測試的網站。

## 採用方式

- Node.js 本機服務，僅監聽 127.0.0.1。管理者用瀏覽器維護目前專案，保存到真正的 raw／Wiki 檔案。
- 不增加雲端帳號或模型金鑰。上傳是使用者手動匯入，不啟動外部搜尋，也不冒稱 AI 已自動讀懂或查證內容。
- GitHub Pages 是靜態託管，公開閱讀站及管理介面展示版可發布；真正寫檔管理仍需本地服務。若日後要求多人雲端後台，再討論有驗證的後端。

## 功能

1. 總覽：條目、來源、待整理資料、檢查結果與最近操作。
2. 來源上傳：文字／Markdown／PDF／CSV／JSON，限制大小，保留原件及 hash；建立來源草稿和待整理工作。
3. 知識管理：搜尋、分類、狀態篩選、建立／編輯條目、Markdown 即時預覽、來源與關聯選擇。
4. 更新維護：保存前檢查，保存歷史版本，更新索引並追加紀錄；避免多人或外部修改造成覆蓋。
5. 健康檢查：呈現工具錯誤與警告，明確區分檔案檢查及事實查證。
6. 操作紀錄與使用指南。索引及 log 不開放任意覆寫，原件不開放修改或刪除。
7. 公開閱讀站從可公開 Wiki 產生，排除 raw、草稿、內部政策、操作紀錄及本地備份。

## 資料與驗收

- 上傳後預設為待整理，不生成茶知識結論。PDF 僅封存，不假裝已擷取或 OCR。
- 本地寫入使用暫存驗證與序列化操作；失敗不留下半套 Wiki。修改已有條目前保存原版，並檢查版本衝突。
- 測試含上傳、重複／非法檔案、保存後重讀、衝突、錯誤回復、跨來源請求、Markdown 安全預覽及公開輸出界線。
- 可用時以本機 Chrome／Edge 實際操作管理網頁並檢查窄螢幕；完整結果寫入測試報告，不用 HTTP 成功代替互動測試。
