檢查日期：2026-11-15。範圍：規則文件、內容指南、模板、分類設定、現有內容與進度。未對外搜尋，未改寫茶知識或製作網頁。

## 結論

原文件已涵蓋作業要求的目的、風格、結構、內容格式、命名、AI 工作流程與延伸方式，能作為後續開發依據。但不宜稱為完全沒有歧義：本輪找到並修正以下七組問題。

| 問題 | 原本可能產生的誤解 | 本輪處理 |
| --- | --- | --- |
| 搜尋與更新的觸發 | 訪客使用站內搜尋框，也會觸發社群研究；或排版調整時擅自補查資料 | 區分站內本地搜尋與協作對話的研究要求；check、build 不觸發對外研究 |
| published 與複核 | 以為資料已上線或已由使用者逐篇確認；不知道誰能轉狀態 | 定義為可供建置，執行 AI 要核對來源並記錄結果，不新增使用者逐篇批准關卡 |
| 文件與階段的關係 | 永久讀到「指令尚未實作」，或沿用指南裡「還沒有條目」的舊狀態 | 固定規則與階段紀錄分開，指令看實際 package.json；修正既有青心烏龍條目的敘述 |
| 內容關聯與網址 | 「可發布條目」可能包含未公開草稿，各頁各自產生網址 | 明定公開關聯只能指向 published，固定頁面路徑及共用連結函式，保留子路徑部署能力 |
| 七天區間與討論比較 | 日期只有年月日時仍強行納入邊界，或用不明綜合分數選熱門 | 明定同批截止、區間及日期不完整的排除方式；可比資料才比較，單貼文不稱多帳號焦點 |
| 詞語驗證與來源呈現 | verified 被當成商品鑑定；每篇基礎文都硬加無關社群帳號 | 定義 verified 的範圍，要求示例性質可見；話題文分列社群與查證來源，基礎文只列相關出處 |
| 舊文章與失效來源 | 把歷史話題直接改成本週；readable 被當成永久有效 | 新一期另建 digest；舊資料保留區間，更正留紀錄；來源可讀狀態有查閱時間，新研究仍需手動授權 |

## 現在已清楚的規則

- 首頁、六大分類與茶名拆解是核心；風格為茶文化雜誌。
- 文章白話口語，專有名詞給解釋與例子；不能為了通俗混淆名詞。
- 使用者手動要求才研究更新，不自動排程。
- 社群發現問題，官方／研究資料協助查證；文末保留具體來源。
- 無合格近期貼文時提供實際限制說明，不虛構熱門話題。
- 新增條目使用模板與穩定 ID，索引、搜尋及版面由後續建置器統一產生。

## 尚待實作驗證，不屬於文字未確認

1. check／build／preview 尚未實作，規則目前是開發與驗收規格，無法宣稱已由工具全面強制執行。
2. 需透過下一階段實際做頁面與新增一篇內容，驗證共用版型、索引、搜尋和交叉連結能運作。
3. 社群樣本能否取得取決於實際可讀資料，文件無法保證每次找到近期熱門主題。
4. GitHub 帳號與部署方式待發布階段依可用連線處理，未指定假網址或宣稱已發布。

本輪修正未改變使用者已確認的主題、六大分類、視覺或更新偏好，沒有新增必須由使用者決策的項目。
