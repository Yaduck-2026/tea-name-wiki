# TeaWIKI｜本人管理、訪客唯讀

日期：2026-11-16。使用者要求：GitHub 上架前，限制只有本人可上傳及編輯，其餘使用者只能觀看。

## 現況與修正

- 公開 GitHub Pages 僅提供靜態閱讀及唯讀管理展示，沒有寫入 API；不能只靠前端停用按鈕當作身分驗證。
- 原版本只監聽 127.0.0.1，但未驗證管理者身分；本輪已修正，不能再僅憑開啟首頁取得管理工作階段。
- 本機管理 API 已加上本人密碼登入；未設定時先由本人在本機設定，未登入不得讀取管理資料、原件、版本或執行寫入。
- 密碼使用 salt 與 scrypt 雜湊保存於被忽略的 .local/，不寫明文、不放前端或公開 Repository。工作階段具有效期與登出。

## 預設權限

| 使用者 | 公開閱讀 | 本機管理資料 | 上傳／編輯／還原／生成公開版本 |
| --- | --- | --- | --- |
| 一般訪客 | 可以 | 不可 | 不可 |
| 未登入的本機瀏覽者 | 可以 | 不可 | 不可 |
| 已登入的本人 | 可以 | 可以 | 可以 |

公開 Repository 的一般訪客能閱讀／複製公開內容，不等於能修改本人的 Repository。不新增寫入協作者，發布工作流程僅由本人手動執行。遠端 Repository 未建立，因此尚未檢查實際帳號／協作者設定。

## 需要確認的使用方式

預設沿用目前架構：本人在本機登入編輯，其他人到 GitHub Pages 看公開內容。若希望本人也能在公開網址登入並寫入，則需另建可驗證身分的後端或 GitHub 授權流程，不能把密碼藏在靜態 JavaScript 當權限控制。

問題：維持本機登入編輯，還是也需要公開網址登入後編輯？此選擇影響後續部署，不影響本輪先補齊本機登入與驗證公開站無寫入 API。

本輪先採本機密碼管理完成保護；線上可寫後台尚未實作，不把這個預設當作使用者已選擇線上部署方式。

## 設定與實際限制

- 第一次在本機設定 10～128 字元密碼，之後登入；密碼由使用者自己輸入，沒有預設密碼，不需要傳給 AI。
- 工作階段最多八小時，登出或重啟服務後原工作階段失效；連續錯誤嘗試有暫時限制。
- 本機密碼設定檔在 .local/admin-auth.json，使用獨立 salt 和 scrypt，不含明文密碼。原始資料仍需自行備份。
- 此設計以本人控制自己的 Windows 帳號及專案檔案為前提；能直接修改電腦上的程式與設定檔者，不能單靠網頁密碼防止。服務維持僅本機，不作多人雲端後台。
- GitHub workflow 增加 actor 必須等於個人 Repository owner 的條件；上架時仍需實際確認沒有其他寫入協作者或額外授權。公開倉庫可被複製，不代表別人可以修改本人的原倉庫。

## 本地驗證結果

- npm test：11／11，含未登入讀寫拒絕、錯密碼、正確登入、重複設定拒絕、登出及舊工作階段失效。
- Chrome：13 類互動檢查，含首次設定、登出、錯密碼與重新登入，原管理及唯讀展示測試維持通過。
- 測試密碼只存在隔離副本，不是使用者本人的密碼；正式本機尚待本人初次設定。

## 驗證要求

未登入 API 拒絕、錯密碼拒絕、正確登入才可操作、登出後失效、跨來源操作拒絕、公開輸出不含登入憑證與寫入服務。瀏覽器驗證本人設定／登入與訪客展示。
